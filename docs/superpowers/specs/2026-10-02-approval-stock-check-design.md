# 승인 시 재고·예약 충돌 자동 확인 설계

## 목적
관리자가 학생 신청을 승인할 때 기자재 대수(재고)와 강의실 예약 충돌을 **직접 세지 않아도 되게** 하고,
**초과·충돌 상태로 승인되는 것을 막는다.**

## 배경 (현재 문제)
- 학생 신청 시점에는 "승인된 건"만 기준으로 재고를 확인하므로, 같은 기간의 승인 대기 건 여러 개가 각각 통과할 수 있다.
- `approveRequestGroup` / `approveClassroomRequest` 는 승인 시점에 재고·충돌을 전혀 확인하지 않는다.
- 그래서 관리자가 대기 건을 승인할 때마다 수량·충돌을 수작업으로 확인해야 하고, 놓치면 초과 승인된다.

## 범위
- 대상: 관리자 **기자재 신청 승인**(기자재 + 부속 공유 재고), **강의실 신청 승인**(기존 승인 예약·정규 수업 충돌).
- 제외: 관리자 수동 등록(의도적 초과 등록 경로로 유지), 학생 신청 시점 검증(변경 없음).

## 결정 사항
1. **기준**: 해당 신청 기간 동안 **승인된(approved)** 대여만 반영. 대기 건은 승인되는 순간부터 반영.
2. **기자재 계산**: 기간 내 **최대 동시 사용량**(sweep). 단순 합산은 서로 겹치지 않는 대여까지 더해 과소 판정하므로 쓰지 않는다. 구간은 반열림 `[start, end)` — 기존 겹침 조건(`startAt < end && endAt > start`)과 동일.
3. **부속**: `sharedStockKey` 가 같은 부속은 한 재고 풀. 총량은 그룹 멤버 총량의 최댓값(기존 `resolveStockGroup` 과 동일). 비활성 부속은 총량 0.
4. **묶음 신청**: 같은 기자재/부속 풀은 묶음 내 요청 수량을 합산. **하나라도 부족하면 묶음 전체 승인 차단.**
5. **강의실**: 같은 강의실의 승인된 예약과 기간이 겹치거나 정규 수업 시간표(`findTimetableConflict`)와 겹치면 충돌. **충돌이 있으면 승인 차단.**
6. **서버 이중 확인**: 승인 액션이 트랜잭션 안에서 다시 계산해, 부족·충돌이면 승인하지 않고 사유를 반환한다.

## 구성
- `src/lib/approvalCheck.ts` (순수): `peakConcurrentUsage`, `makeStockLine`, `summarizeStock`, 타입(`StockLine`, `GroupStockResult`).
- `src/lib/approvalCheck.server.ts` (DB): `checkEquipmentGroupsStock(groups, db)`, `checkClassroomConflicts(rows, db)`. `db` 인자로 트랜잭션 클라이언트를 받는다.
- `src/app/actions/admin.ts`: `approveRequestGroup` / `approveRequest` / `approveClassroomRequest` 가 `ApproveResult` 반환, 부족·충돌 시 차단.
- `src/components/admin/ActionModal.tsx`: 승인 확인창에 재고 확인 표 / 충돌 목록 표시, 차단 시 "승인 확정" 비활성화, 서버 거절 사유 표시.
- 화면: `admin/requests`(기자재·강의실 탭), `admin/classroom` — 승인 대기 건에 품목별 "가용 n / 총 m"·부족 표시, "승인 가능 / 재고 부족·충돌" 배지.

## 화면 동작
- 대기 건 품목마다 `가용 3/10`(초록) 또는 `가용 1/10 · 2개 부족`(빨강). 부속은 부족할 때만 `(n개 부족)`.
- 상태 칸에 `승인 가능`(초록) / `재고 부족`·`예약 충돌`(빨강) 배지와 부족·충돌 요약.
- 승인 확인창: 차단 시 "재고가 부족한(또는 예약이 겹치는) 항목이 있어 승인할 수 없습니다. 거절하거나, 꼭 필요하면 수동 등록으로 처리하세요."
- 승인 후 페이지 재검증으로 같은 기간 다른 대기 건 수치가 즉시 갱신된다.

## 오류 처리
- 이미 처리된 신청을 승인하려 하면 "승인 대기 중인 신청이 없습니다(이미 처리되었을 수 있음)".
- 서버가 차단하면 확인창이 닫히지 않고 최신 부족/충돌 목록을 보여준다.

## 테스트
- 순수 함수 단위 테스트(겹침·경계·동시 사용 최대치·클리핑·부족 계산), TZ=UTC/Asia-Seoul.
- 실제 DB 디버그 라우트로 서버 확인(부족 차단·충분 승인·강의실 충돌)을 검증 후 테스트 데이터 정리.
- 화면: 대기 건 배지·확인창 차단 확인.

## 구현 단계
1. 순수 lib + 단위 테스트(TDD)
2. 서버 lib(기자재 재고·강의실 충돌)
3. 승인 액션 차단 + 반환 타입
4. 확인창 UI
5. 목록 화면(requests 기자재·강의실 탭, admin/classroom)
6. DB 검증 → 배포
